# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal portfolio (Jekyll on GitHub Pages) plus a chat assistant backed by Amazon Bedrock. No JS build step, bundler, or linter; JS is native ES modules served as-is. Owner constraint: keep everything free — GitHub Pages only, plus the Bedrock chat API on Vercel. Don't add paid services or a custom Pages deploy workflow.

## Commands

- Local site: `bundle install && bundle exec jekyll serve` (only core Liquid is used, so plain `jekyll build` works too).
- Chat API tests: `cd bedrock-api && pip install boto3 && python -m unittest tests/test_api.py`.
- Refresh the repo index manually: `python3 .github/scripts/update_repos.py` (public GitHub API, no token needed).

## Architecture

1. **Static frontend** — `index.html` composes `_includes/sections/*.html` (hero, about, stack, projects, open-source = Repos, experience, contact, portrait-fly) in `_layouts/default.html`, plus the pill navbar/menu overlay (`site-header.html`), the footer with the halftone portrait band (`site-footer.html`) and the Ask AI drawer (`chat-widget.html`). CSS is split into `fonts/tokens/base/layout/components/chat/responsive`; fonts are self-hosted in `assets/fonts` (Inter variable, JetBrains Mono). `_config.yml` supplies `portfolio_api_url` (exposed as `window.PORTFOLIO_API_URL`) and `resume_url` (empty ⇒ the Résumé chip is a placeholder that shows a toast). New non-site top-level files must be added to `exclude:`.
2. **JS** — `assets/js/app.js` is the single entry (cache-busted by build time); it loads every feature as a cache-busted dynamic import so one failure can't break the page. Modules: `theme` (dark default, light toggle, dispatches `themechange`), `navigation` (pill nav + overlay), `hero` (kinetic 3D title + cursor-spotlight canvas), `portrait` (scroll-linked flip/travel of the portrait card from hero to About; disabled ≤900px and for reduced motion), `folders` (project `<dialog>` case studies), `timeline` (scroll-drawn sine wave, vertical on narrow screens), `contact` (mailto draft + glyph burst on the Résumé placeholder), `crowd` (footer halftone portrait that reassembles each time it scrolls in, plus drifting word streams), `reveal` (scroll-scrubbed section scenes), plus `repositories` and `chat`. `scroll.js` is the shared rAF scroll loop. Everything respects `prefers-reduced-motion`.
3. **Repo index** — `public-repos.json` is a snapshot generated by running `.github/scripts/update_repos.py` manually and committing (no Actions workflows: the account's Actions are billing-locked); it also stores a README-derived `summary` for repos with no GitHub description. `repositories.js` renders the snapshot (or the visitor's cached live copy) first, then fetches the live list from the public GitHub API (1-hour localStorage cache, Refresh button, snapshot fallback). Written-up projects are the `[data-repo]` articles inside the `<dialog class="case">` elements in `projects.html` (each with a hand-drawn inline SVG flow diagram); every other repo (minus the site repo and profile repo) appears as a card under "Repos".
4. **Design and copy** — Monochrome editorial: near-black canvas, white pills for primary actions, hairline borders, bold tight Inter for display type, sentence-case JetBrains Mono micro-labels (no uppercase tracking, no negative tracking under 16px). Nothing loops unless it is live, and headings carry no trailing period. Spacing tokens live in `tokens.css`: `--section-y` (vertical padding for every section) and `--edge` (the shell's edge, for full-bleed blocks that must line up with it). The case-study dialog spacing is owner-approved; leave it alone unless asked. Light theme is the same page inverted; the footer, folders and chat drawer stay dark in both. The footer portrait is a canvas halftone drawn from `assets/illustrations/portrait-dots.json` (the photo sampled to a 100x100 grid of dot sizes, 0-35 encoded as base-36 characters). Copy is first person and plain; facts come from the owner's résumé and public repos only. Patterns removed earlier for reading as AI-generated; don't reintroduce them: slogan heroes, one headline formula repeated across sections, numbered all-caps kickers, lists of three, aphorism cards, abstract filler sentences, boilerplate card labels, fake metadata, unverifiable claims or invented facts, an arrow on every link, em-dashes as default punctuation, filter/search bars for a handful of items, one generic fade-in reused on every block, and intro tickers. Instead every section is a scroll scene scrubbed like the timeline wave (owner request): `reveal.js` writes `--p` (0..1, smoothed) on each `[data-scrub="enter,exit"]` element from its layout position, building as it comes in from either edge and unwinding as it leaves, so it replays on every pass; CSS under "Scroll scenes" in `components.css` turns it into motion via the independent `translate`/`rotate`/`scale` properties. Headings tumble up word by word, About text inks in as you read and its numbers count, Stack tags fly in from a scatter, project folders tip up and open at mid-screen (`--c`), a scanner sweeps the Repos rows, certifications flip like a split-flap board, the contact email decodes, and the footer portrait reassembles each visit. Anything carrying information (numbers, the email) must finish by the time its block is mid-screen. The only progress indicator is the 2px reading hairline. Earlier themes (drawing-sheet, navy/blue) were tried and replaced at the owner's request.
5. **Chat API (`bedrock-api/`)** — Vercel Python function (`api/index.py` → `core.py`, `ratelimit.py`). Bedrock Converse, model `global.moonshotai.kimi-k3.1`, `ap-southeast-2`. Facts the model may use live in `PORTFOLIO_CONTEXT` in `core.py` — update it when site content changes. Output tokens are capped low on purpose (cost); the per-IP rate limiter is best-effort per warm instance. Secrets are Vercel env vars (see `DEPLOYMENT.md`).
