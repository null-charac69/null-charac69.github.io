# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal portfolio (Jekyll on GitHub Pages) plus a chat assistant backed by Amazon Bedrock. No JS build step, bundler, or linter; JS is native ES modules served as-is. Owner constraint: keep everything free — GitHub Pages only, plus the Bedrock chat API on Vercel. Don't add paid services or a custom Pages deploy workflow.

## Commands

- Local site: `bundle install && bundle exec jekyll serve` (only core Liquid is used, so plain `jekyll build` works too).
- Chat API tests: `cd bedrock-api && pip install boto3 && python -m unittest tests/test_api.py`.
- Refresh the repo index manually: `python3 .github/scripts/update_repos.py` (public GitHub API, no token needed).

## Architecture

1. **Static frontend** — `index.html` composes `_includes/sections/*.html` in `_layouts/default.html`. CSS is split into `fonts/tokens/base/layout/components/responsive`; fonts are self-hosted in `assets/fonts`. `_config.yml` supplies `portfolio_api_url` (exposed as `window.PORTFOLIO_API_URL`) and `resume_url` (empty ⇒ "coming soon" placeholder). New non-site top-level files must be added to `exclude:`.
2. **JS** — `assets/js/app.js` is the single entry (cache-busted by build time). It runs theme/navigation/reveal/filters directly and dynamically imports `modules/repositories.js` and `modules/chat.js`, so one failure can't break the page. `chat.js` has its own small markdown renderer.
3. **Repo index** — `public-repos.json` is generated by `.github/workflows/update-repo-index.yml` (daily cron, free) via `.github/scripts/update_repos.py`; `repositories.js` reads it same-origin. Featured cards are the `[data-repo]` elements in `projects.html`; every other repo appears in the "workbench" grid.
4. **Chat API (`bedrock-api/`)** — Vercel Python function (`api/index.py` → `core.py`, `ratelimit.py`). Bedrock Converse, model `global.moonshotai.kimi-k3.1`, `ap-southeast-2`. Facts the model may use live in `PORTFOLIO_CONTEXT` in `core.py` — update it when site content changes. Output tokens are capped low on purpose (cost); the per-IP rate limiter is best-effort per warm instance. Secrets are Vercel env vars (see `DEPLOYMENT.md`).
